## The architecture rule that overrides everything

> **Every numeric rule -- curve, threshold, table, formula -- goes into `Assets/Scripts/Rules/`, in
> a static class WITHOUT any engine dependency, with its tests.** The `MonoBehaviour`s delegate.

That is what makes the game tunable: those tests run in a few milliseconds because they never touch
the engine, and the `run-rules-tests.ps1` hook replays them at every edit. A class in `Rules/` that
would need `using UnityEngine` signals a bad split -- it is up to the caller to do the engine work.

Tests do not aim at line coverage but at **intent regressions**: a test must lock down *what the
design forbids*, not paraphrase the implementation.

## The scene is an artefact, not a source

`Assets/Scenes/Game.unity` is **regenerated by `SceneBuilder.Build()`** at every build. To add an
object to the game, you write code in `SceneBuilder`, you do not click in the editor. In exchange,
the whole game can be driven in batchmode -- that is what lets you check your own work.

WARNING: corollary -- the scene comes out **modified after every build** (every `fileID`
renumbered). Discard it (`git checkout --`) unless `SceneBuilder.cs` has changed.

## Non-negotiable conventions

- PascalCase for classes/methods, `_camelCase` for private fields, `readonly` by default.
- **Nothing deprecated**: URP (never Built-in), Input System package (never the old Input Manager).
  If a deprecation warning shows up in a log, report it without waiting to be asked -- that is an
  explicit instruction from the project owner.
- WARNING: **the project owner's keyboard is AZERTY.** `KeyCode` and `Key` both designate a
  **physical position on a QWERTY keyboard**, never the printed character: `Key.A` falls under the
  key marked **Q**. That is the intended behaviour, not a bug. Corollary: avoid `A`, `Q`, `Z`, `W`,
  `M` for global shortcuts -- prefer `Tab`, `R`, the digits or the arrow keys, whose position is
  common to both layouts.
- **Never a hard-coded colour** nor an ad hoc style: go through the project palette.
- **Never hard-coded text** if the game is localised.
- Tuning must be adjustable **without recompiling** (JSON in `StreamingAssets/` or a
  ScriptableObject) as soon as a value deserves to be tried several times.
- Comments in English, and they explain the **why**. A comment that paraphrases the code is noise;
  the one that says "without this safeguard, a 2nd boss appeared every 28 s" prevents a regression.
